# Rules

Generated by okf-check 0.3.0 (ruleset 49f891584e77). Do not edit: regenerate with okf-check skill --no-profile.

Every rule `okf-check check` applies. A finding in `findings.json` names its rule without the `repo.` or `profile.` prefix this table shows. Only an `error` finding fails the check; a `warning` is reported and the check still passes.

## Repo rules (every repository)

| Rule | Severity | Runs | What it means | How to fix |
|------|----------|------|---------------|------------|
| `repo.path-not-uploadable` | error | always | A file in the bundle is one the instance reader would not upload (a symbolic link, a path with a dot component, or a name the reader skips), so git would hold a file the knowledge base never ingests. | Remove the file or move it outside the bundle directory. |
| `repo.stamp-schema` | error | always | A `verified` entry has the wrong shape; a string entry (`- human:alice`) is read by the platform as machine-confirmed, so it can forge or silently drop a review. | Write every `verified` entry as a mapping: `- {by: agent:okf-agent, at: YYYY-MM-DD}`. |
| `repo.stamp-stale` | warning | always | A well-formed `reviewed_hash` no longer matches the document body, so the human review is out of date and the document's trust is overstated. | Leave the review fields alone and ask a maintainer to review the changed body again. |
| `repo.immutability` | error | with --base | A document that exists at the base is missing from the bundle: it was deleted or renamed, and a rename is a delete plus an add. | Restore the file at the same path and set `status: deprecated` in place; put new content under its own path. |
| `repo.human-stamp-change` | error; warning with trusted review | with --base | A `human:` entry in `verified` was added or altered against the base, or the review fields of a human-reviewed document changed; authorship is never consulted. | Never write a `human:` entry; a maintainer adds one through the trusted-review flow. |
| `repo.profile-config-change` | error; warning with trusted review | with --base | The runbook-profile configuration `.okf/profile.json` was removed, added or changed against the base, whether or not the profile is on. | Do not edit `.okf/`; a code owner changes the profile configuration. |
| `repo.index-line-missing` | warning | always | A concept document is not listed by its own directory's `index.md`, or that directory has no `index.md`. | Add the entry line `* [Title](file.md) - description` to the same directory's `index.md`, creating it when absent. |

## Runbook profile rules (runbook profile only)

These run only in a repository whose `.okf/profile.json` turns the runbook profile on.

| Rule | Severity | Runs | What it means | How to fix |
|------|----------|------|---------------|------------|
| `profile.sub-heading` | error | runbook profile only | A heading line in a runbook body would split the runbook into several chunks. | Use a bold label instead of a heading. |
| `profile.size-cap` | error | runbook profile only | A runbook's title plus body is over the 1100 code point cap, so it would not fit one chunk. | Shorten the runbook or split it into two documents. |
| `profile.codes-in-body` | error | runbook profile only | A code listed in the `codes` frontmatter does not appear literally in the body. | Name each listed code in the body, or remove it from `codes`. |
| `profile.review-stamp` | error | runbook profile only | A document with a `human:` entry lacks `reviewed_at`, lacks a well-formed `reviewed_hash`, or carries a stale one. | Do not add or change review fields; a maintainer redoes the review. |
| `profile.verified` | error | runbook profile only | `verified` is not a non-empty list of `{by, at}` mappings, `by` is not `agent:<id>` or `human:<id>`, or `at` is not a `YYYY-MM-DD` date. | Write `verified` as a list of `{by: agent:<id>, at: YYYY-MM-DD}` mappings. |
| `profile.frontmatter` | error | runbook profile only | A document's frontmatter does not split or does not parse to a mapping. | Start the file with a `---` fenced YAML mapping and close it with `---`. |
| `profile.type` | error | runbook profile only | `type` is neither `Runbook` nor `Index`, a file named `index.md` is not `type: Index`, or another file has `type: Index`. | Give runbooks `type: Runbook` and every `index.md` `type: Index`, and use `Index` only for `index.md`. |
| `profile.line-endings` | error | runbook profile only | A document contains a carriage return byte. | Save the file with LF line endings only. |
| `profile.sections` | error | runbook profile only | A runbook does not have the five bold labels Symptoms, Cause, Confirm, Fix and Operator fix, once each, in that order, each with text. | Add the missing label on its own line, in order, with at least one line of text under it. |
| `profile.status` | error | runbook profile only | `status` is not `stable` or `deprecated`. | Set `status: stable`, or `status: deprecated` to retire the document in place. |
| `profile.empty-bundle` | error | runbook profile only | The bundle holds no document of `type: Runbook`. | Add at least one runbook, or check that `bundle_root` points at the right directory. |
| `profile.bundle-files` | error | runbook profile only | A file git holds is one the instance reader drops, such as a symbolic link, a non-markdown file, a dot-component path or a scaffolding name like README.md. | Remove the file from the bundle directory or move it outside it. |
| `profile.stem-collision` | error | runbook profile only | Two documents would become the same entity id, which aborts the ingest. | Rename the later document so its file name stem is unique (a new file name, never a rename of a published one). |
| `profile.hygiene` | error | runbook profile only | A document contains something that looks like a secret or an account identifier: a 12-digit number, a JWT-shaped string, an AWS access key id, an `sk-` style key or a PEM header. | Delete the value, or write a placeholder such as <account-id>. |
| `profile.recipe` | error | runbook profile only | A `recipe` value is not a string id, or names a recipe the profile configuration does not list. | Use one of the recipe names the profile reference lists. |
| `profile.codes-known` | error | runbook profile only | `codes` is not a list of strings, or names a code the profile configuration does not know. | List only known env_health codes, each as a string. |
| `profile.sources` | error | runbook profile only | `sources` is not a non-empty list of `{title, resource}` mappings, or a `resource` is not a git-tracked, repository-relative path without `..`. | Cite a tracked repository path; an issue URL is not a valid resource under the profile. |
| `profile.operator-fix` | error | runbook profile only | The Operator fix section is empty, lacks the command stem of a named recipe, or contains an unsafe command form (a bare `just refresh-merged-api`, `--target` after `cargo pmcp deploy`, `--regenerate-stack` or `--force` on a cargo pmcp line). | Write the exact command stem of each recipe the runbook names and remove any unsafe command. |
| `profile.customer-fix` | error | runbook profile only | The customer-facing Fix section carries an operator command, or does not name a recipe id in backticks. | Keep operator commands in the Operator fix section; in Fix, ask the operator to run the named recipe in backticks. |
