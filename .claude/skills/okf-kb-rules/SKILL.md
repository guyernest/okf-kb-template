# OKF knowledge base rules

Generated by okf-check 0.3.0 (ruleset 49f891584e77). Do not edit: regenerate with okf-check skill --no-profile.

## Who this skill is for

Two readers use this skill and it gives both the same rules: the okf-agent, which answers a knowledge-base issue by opening a pull request, and a maintainer who works on this repository locally with Claude Code.

- **Agent only:** the never-list below, the `agent:okf-agent` provenance entry in the recipes, and the `okf-agent-check` wrapper.
- **Everyone:** every rule in `references/rules.md`, the index-line convention and the retire-in-place convention. A maintainer follows them too, except that a maintainer may add a `human:` review stamp through the trusted-review flow in `.github/okf/CI.md`.

## The bundle and the check

The knowledge base is the directory named by `bundle_root` in `.okf/publish.toml`; every change is a markdown file inside it. `okf-check` validates a pull request with the same engine the platform uses to build the knowledge base: what the platform would refuse, the check refuses. Warnings are reported and never block a merge; errors do.

## Runbook profile

A repository that holds `.okf/profile.json` has the runbook profile on. Its extra rules are the rows marked "runbook profile only" in `references/rules.md`; without that file none of them run. The okf-agent always receives `references/profile.md`, rendered by the pinned engine for this repository, and follows it. A maintainer renders the same reference locally:

```
okf-check skill --out /tmp/okf-kb-rules --repo-root .
```

and reads `/tmp/okf-kb-rules/references/profile.md`. That reference is never committed: it is rendered on demand, so it always matches the engine you run.

## Never (the okf-agent)

These bind the okf-agent. The pull-request pipeline checks each of them again after the agent finishes, and a violation fails the run.

- Never write a `verified` entry whose `by` starts with `human:`. Only a person stamps a document as human-reviewed.
- Never change a file outside `bundle_root`, the directory named in `.okf/publish.toml`.
- Never delete or rename a document. Retire one in place with `status: deprecated` (see the retire recipe).
- Never edit `.okf/`, `.github/`, `.claude/`, `scripts/` or `CODEOWNERS`. They are the repository's own controls, and the skill itself lives in `.claude/`.
